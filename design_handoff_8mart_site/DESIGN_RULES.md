# Скилл: редизайн сайта → UI Kit → адаптив → handoff

Агент обязан следовать этому файлу на протяжении всей работы.

## 0. Роль
Ты — продуктовый дизайнер и фронтенд-архитектор. Работаем итеративно: сначала понимаем, потом строим систему, потом экраны, потом отдаём в код. Не переходи к следующему этапу, не закрыв предыдущий.

## 1. Сначала вопросы (одна форма, до 10 вопросов)
Прежде чем рисовать что-либо, задай форму вопросов. Обязательно:
- **Что за сайт и цель редизайна** — что не работает сейчас (конверсия, устарел визуально, неудобно на мобиле, нет системы).
- **Что сохранить** — логотип, цвета, шрифт, структуру, тексты. Попроси ссылку на текущий сайт и/или скриншоты, логотип SVG, брендбук.
- **Ключевые сценарии** — 2–3 главных пути пользователя (например: выбрать → в корзину → оформить → оплатить). Экраны делаем только под них.
- **Аудитория и устройства** — доля мобильного трафика; какие брейкпоинты важны (390 / 768 / 1440).
- **Есть ли код** — репозиторий или папка (code-source вопрос). Если есть — стек, компоненты, роутинг, что уже реализовано.
- **Бэкенд/интеграции** — какие API уже есть, платёжки (Kaspi, карты), карты, авторизация. Что данные, а что статика.
- **Тон и референсы** — 2–3 сайта, которые нравятся, и чем именно.
- **Объём** — сколько экранов, нужны ли состояния (пусто/ошибка/загрузка), нужны ли варианты для сравнения.
- **Результат** — только макеты, или ещё адаптивная HTML-версия для теста в браузере + пакет для разработчика.

Если ответ неполный — задай уточняющий раунд только по тому, что меняет решение. Не переспрашивай то, что уже сказано.

## 2. Аудит текущего сайта (до дизайна)
Пройди по сайту/коду и зафиксируй в `AUDIT.md`: структура страниц, реальные тексты и цены, используемые цвета/шрифты, повторяющиеся элементы, проблемы UX. Реальный контент — источник правды; никаких «Lorem ipsum» и придуманных цен.

## 3. UI Kit — первым, до экранов
Создай `UI Kit.dc.html` как единый источник правды и обновляй его при каждом изменении:
- **Токены**: цвета (primary + оттенки 50/100/200, ink 1–3, surfaces, две линии border/divider, semantic), шрифт и шкала, шаг отступов 4, радиусы, высоты контролов (одна шкала, например 36/40/44/56/60), тени, motion.
- **Компоненты с состояниями**: default / hover / active / focus / disabled / error / loading / empty. Инпут — с маской, обязательностью `*`, кнопкой очистки. Кнопка — все размеры и варианты (primary/secondary/ghost/danger + split-CTA «текст · сумма»).
- **Правило переиспользования**: элемент, повторяющийся ≥3 раз или имеющий состояния, выносится в отдельный компонент (`FritoInput.dc.html` и т.п.) и подключается в экраны через `dc-import` — не копируется руками. Никаких «почти таких же» кнопок с другой высотой.
- Одно значение — одно место: пороги (например бесплатная доставка), комиссии, тексты ошибок лежат в `data.js`, а не захардкожены в двух экранах по-разному.

## 4. Экраны
- Сначала desktop и mobile главного сценария, потом остальные. На каждом экране — все состояния сценария (пусто, ошибка, распродано, disabled CTA), переключаемые через Tweaks.
- Каждый экран собирается из UI Kit. Если понадобился новый элемент — сначала добавь его в Kit.
- Перед показом сверь экраны с Kit: цвета линий, высоты кнопок, радиусы, размеры иконок. Расхождения — исправить, а не документировать.
- Варианты для сравнения — в одном файле, с id (1a, 1b…), а не в десяти файлах.

## 5. Адаптив
Артборды 1440/390 — для дизайна. Для теста делается отдельная fluid-версия (`Site.dc.html`): один экран, переключение desktop↔mobile по брейкпоинту (например 1024), мобильная раскладка ограничена ~600px по центру. Экраны связаны реальными ссылками (меню → оформление → назад). Собирается в самодостаточный `.html`, который открывается двойным кликом.

## 6. Handoff — обязательный финал
Папка `design_handoff_<проект>/`:
- `README.md` — обзор, fidelity, экраны с размерами, интеракции, стейт, **API-контракт** (какие эндпоинты и какая форма данных нужна фронту), известные несоответствия, промпт для Claude Code.
- `tokens.css`, `COMPONENTS.md` (спека каждого компонента: размеры, состояния, props).
- `screens/`, `components/`, `site/` (адаптивные исходники + runtime), `preview/` (самодостаточные html), `assets/`, `data.js`.
- В README явно: HTML — референс, а не production-код; воссоздать в стеке проекта; данные заменить на API, сохранив форму объектов.

## 6.5. Обязательные стандарты (не переспрашивать, делать всегда так)
**Материалы — запросить файлом в первой форме (вопрос типа «файл»):**
- Логотип — SVG (светлая и тёмная версии, если есть). Пока не прислали — текстовый fallback названием, никаких нарисованных «логотипов».
- Кнопка Kaspi Pay — официальный SVG от банка. Использовать как есть, только радиус подогнать под нашу шкалу (pill). Не перерисовывать.
- Иконки соцсетей / мессенджеров, фото товаров или ссылка на CDN, брендбук.

**Телефон:**
- Маска `+7 (999) 999-99-99`. Ведущая `8` заменяется на `+7` (так набирают пользователи). Если после `+` код не 7 — свободный международный формат без маски.
- Без кнопки очистки. Обязательное поле — красная `*` в лейбле. Маска считается только по цифрам: Backspace на символе маски стирает соседнюю цифру, пустое поле — действительно пустое.

**Инпуты:**
- Плавающий лейбл, одна высота (56), textarea 84. Кнопка очистки `×` — только когда поле в фокусе и заполнено.
- Обязательные поля — `*` в лейбле; текст «необязательно» не писать.
- Состояния: default / focus (кастомное кольцо, не браузерное) / error с текстом под полем / disabled.

**Промокод:**
- Поле + «Применить»; после применения — плашка с кодом и `×`. Три ошибки: не найден / истёк / не достигнута минимальная сумма (с суммой в тексте).

**Кнопки оплаты / CTA:**
- Основной CTA всегда «текст · разделитель · сумма». Kaspi — официальный SVG кнопки как есть, без суммы (сумма только в итогах); логотип Kaspi `assets/kaspi-logo.svg` — в выборе способа оплаты; карта — primary; способы оплаты — только Kaspi и карта (наличных нет); у вошедшего пользователя в оформлении: верхний уровень — «Kaspi Pay» / «Картой онлайн»; при выборе карты ниже серый блок «Сохранённые карты» (`CARDS`, «Visa •• 4821 · до 09/28», основная выбрана по умолчанию), под разделителем — «Новой картой» с пунктирной рамкой и «+». Логотип Kaspi не перекрашивать.
- Чекбокс оферты — в потоке формы (после оплаты / состава заказа), не в закреплённой панели с CTA. На mobile в оформлении есть блок состава заказа, как на desktop.
- CTA disabled, пока не выполнены условия (согласие с офертой, распроданные товары не удалены), с объяснением почему.

**Корзина:**
- Распроданный товар остаётся в списке, помечен, не считается в сумме и количестве; сверху алерт; CTA заблокирован до удаления.
- Заголовок с правильным склонением «N товар / товара / товаров».
- Способ получения (доставка/самовывоз) выбирается до первого добавления; пока не выбран — модалка выбора. Корзина и способ переживают переход между страницами. Модалку можно закрыть всегда (крестик); если способ не выбран — в шапке остаётся «Как получить заказ?», а попытка добавить товар открывает модалку снова.

**Авторизация:**
- Основной способ — 4-значный код в **WhatsApp**; альтернатива — **Telegram-бот** (открыть бота → «Старт» → «Поделиться номером» → ждём подтверждения, сайт получает номер от бэкенда). На desktop — QR-код на бота (deep-link `t.me/<bot>?start=<token сессии>`) + кнопка «Открыть Telegram на компьютере»; на mobile — только кнопка. Бот пока мок (`TG_BOT` в data.js). Ссылка «Нет WhatsApp? Войти через Telegram» на шаге кода.
- Код: 4 ячейки поверх одного скрытого инпута (клик по ячейкам фокусирует, Backspace стирает, вставка/автозаполнение `one-time-code`), проверка автоматически на 4-й цифре, успех — ячейки зелёные → дальше. Новый пользователь → шаг «Как вас зовут?».

**Статус заказа** (после оплаты): шкала этапов — доставка: Принят → Собираем → Курьер в пути → Доставлен; самовывоз: Принят → Собираем → Готов к выдаче → Выдан. «Отменить заказ» — только до передачи курьеру / готовности, с подтверждением и текстом о возврате; статус «Отменён». Контакт поддержки — WhatsApp (`SUPPORT_WA` в data.js). Курьера на карте не показываем.

**Личный кабинет** (`06 Личный кабинет.dc.html`, контент разделов — `MartAccount.dc.html`): разделы — Мои заказы (активный сверху + история, «Повторить» кладёт товары в корзину, «Подробнее» → статусная страница), Избранное, Адреса (основной, добавить/изменить/удалить), Способы оплаты (Kaspi без привязки; карты сохраняет шлюз, только маска), Промокоды (копировать), Бонусы (правила — мок `BONUS`), Личные данные (имя; смена телефона — код в WhatsApp через `MartAuth purpose="changePhone"`; «Удалить аккаунт» — серой ссылкой внизу, с подтверждением). Desktop — сайдбар + контент; mobile — вкладка «Профиль» в таб-баре → список разделов → экран раздела. Состояние загрузки — скелетоны.

**Бонусы:** 1 бонус = 1 тг, не сгорают. Начисление — у каждого товара своё (`product.bonus` за 1 шт; нет поля — нет бонусов), приходят после получения заказа. Списать можно до `BONUS.maxPart`% суммы товаров (переключатель в оформлении). Показ: зелёная монетка с «Б» (#1DA765, текст #13824D на #EAF7F0) «+N» в карточке товара и строке корзины; «+N бонусов начислим после получения» в итогах корзины/оформления/статуса; «Начислено +N» у выполненного заказа; при отмене — «Вернём N бонусов». Правила — мок, уточнить у бизнеса.
**Адрес в кабинете:** добавить/изменить — та же модалка с картой (`MartMethodModal address-only`). **Удаление аккаунта** → главная с сообщением «Аккаунт удалён».

**Деньги и текст:**
- Формат `4 090 тг.` (пробел-разделитель тысяч, «тг.» с точкой) в ценах; в свободном тексте «тг» без точки.
- Крестики закрытия и стрелки — геометрией (CSS/SVG), не символами шрифта.

**Ассортимент 8mart:** продуктов и готовой еды нет. Категории: Стройматериалы, Инструменты, Для дома, Подарки, Цветы (вместо общего «Товары»; ассортимент новых — мок). Иконки категорий (пластилин, assets/cat-*.png) и фото товаров (на белом, assets/b-*.png, assets/p-*.png) — сгенерированы в Magnific; в проде заменить фото из API.

**Выбор способа получения:** модалка = карта (**Mapbox GL** в `map.html`, встраивается iframe; контракт сообщений карта↔модалка — postMessage `8mart-map`/`8mart-parent`) + свич Доставка/Самовывоз + город из списка. Доставка: пин по центру, адрес определяется по пину (обратное геокодирование) и правится вручную. Самовывоз: точки на карте синхронизированы со списком. Города и точки — в data.js (CITIES, PICKUP_POINTS).
**Подсказки адреса** (поле «Улица, дом»): с 3 символов, debounce 300 мс, до 6 вариантов в пределах выбранного города (**DaData** `suggest/address` + `geolocate/address`, запасной — Mapbox Geocoding v6; всё в `geo.js`. Прототип зовёт DaData из браузера API-ключом; в проде — только через бэкенд `GET /geo/suggest`, `GET /geo/reverse`, secret-ключ во фронт не кладём). Список под полем, строка 48 (mobile 56): заголовок улица+дом / название места, подпись район·город. Клавиатура ↑↓ Enter Esc, тап/клик. Выбор → карта летит к точке, пин ставится без повторного геокодирования. Улица без дома → в поле «Улица, » и курсор остаётся для номера дома. Состояния: загрузка / ничего не нашли / сервис недоступен (→ «поставьте пин»).

**Избранное:** сердце в правом верхнем углу фото карточки (контур #6B6873 → заливка #EE1D74). Общий стор `getFavorites/setFavorite/onFavorites` в data.js — синхронно на всех экранах и в кабинете; пусто → «Пока пусто».
**Каталог** (`07 Каталог.dc.html`): корень (плитки категорий) → категория (плитки подкатегорий + «Все товары») → список. Desktop: сайдбар категорий + фильтры, сетка 4 в ряд, мини-корзина справа. Mobile: чипсы подкатегорий, кнопки «Фильтры»/сортировка → bottom sheet. Сортировки — `SORTS`, фильтры — цена + `CAT_FILTERS` по категории (стройматериалы: фасовка; цветы: размер, цвет). Бесконечная прокрутка по `PAGE_SIZE`, в конце «Это все товары». Клик по карточке → быстрый просмотр (desktop — модалка, mobile — sheet). Цветы — один товар: размер S/M/L (`variants`, у каждого своя цена) и цвет (`colors`) выбираются в быстром просмотре; в карточке цена «от …»; позиция корзины `<variantId>|<цвет>` (`cartItem()`). Цены цветов — мок. Популярность — порядок из API (рейтинга нет).
**Mobile с таб-баром:** отдельной плавающей кнопки «N товаров · сумма» над таб-баром нет — в корзину ведёт вкладка таб-бара со счётчиком. Закреплённая снизу панель с CTA (корзина, оформление) — белый фон, линия сверху #EEEDF1.
**Карточка товара (быстрый просмотр)** — `MartProductView.dc.html` (desktop — модалка 1040, галерея слева sticky + миниатюры/стрелки/←→; mobile — sheet 94%, свайп-галерея с точками, CTA закреплён снизу). Состав: несколько фото (`images`, нет фото → плейсхолдер), фасовки (товары одной `group`), размер (`variants`), цвет (`colors` + `COLOR_SWATCH`), бонусы, CTA, блок «Доставка / Самовывоз» по типу товара (`DELIVERY_TYPES`: express / cargo — тяжёлое, грузовой на следующий день, самовывоз только со склада / flowers), выбранный способ — первым с меткой «Ваш способ». Описание свёрнуто до ~5 строк с градиентом → «Читать полностью»; характеристики — первые 6 → «Все характеристики · N». Esc закрывает. Избранное: desktop — на фото слева сверху (подальше от крестика), mobile — рядом с названием. «Поделиться» (mobile — системный share, desktop — копирует ссылку) и «Страница товара» (только desktop) → `08 Товар.dc.html?id=…` (тот же компонент с `page`, без оверлея/крестика). Условия получения задаются на товаре (`product.conditions`, поля поверх шаблона `DELIVERY_TYPES`), заполняет бизнес.
**Карточки товара:** одинаковая высота в сетке (`align-items:stretch`, название фиксированно в 2 строки, низ прижат).

**Несколько отправлений (тяжёлые товары):** `product.delivery === 'cargo'` → Газель на следующий день (тариф по весу `SHIPPING.cargo.tiers`, `product.weightKg`), остальные — курьер сегодня. Если в корзине оба типа — выбор `MartSplitChoice`: «Двумя доставками» (по умолчанию) / «Всё вместе завтра» (одна Газель). Самовывоз: тяжёлое — только со склада завтра; «Забрать в два приёма» / «Всё завтра со склада». Корзина и оформление группируют товары по отправлениям (`MartShipmentHead`: метка «Доставка 1 из 2», когда, машина · вес, стоимость); в итогах — строка стоимости на каждое отправление. Бесплатная доставка от порога — только курьер; Газель платная всегда. В оформлении у Газели свой выбор дня и интервала + переключатель «Подъём на этаж» (`liftFee` × шт × (этаж−1)). Статус: своя шкала на каждое отправление (Газель: Принят → Собираем → Газель в пути → Доставлен; водитель вместо курьера). Отмена — всего заказа, пока ни одно отправление не передано в доставку. Логика — `planShipments()` / `splitOptions()` в data.js.

**Шапка desktop:** корзины в шапке нет; справа — кнопка меню (бургер + аватар / «Войти»). Отдельных кнопок «Войти»/«Профиль» нет. Меню — боковая панель справа 420 (затемнение, крестик, Esc, клик по фону): гость — плашка «Войдите» + «Войти»; пользователь — имя/телефон, активный заказ со статусом, разделы кабинета со счётчиками, «Выйти» серым. Далее у всех — категории каталога и поддержка (WhatsApp, телефон).
**Мини-корзина desktop** (`MartMiniCart`, колонка 340 справа, sticky): на главной, в каталоге, поиске, странице товара, в кабинете. Нет на корзине и оформлении (там свой состав заказа). Доставка в ней считается через `planShipments()`. Сетка товаров рядом с ней — 4 в ряд.

**Приложение (Flutter, iOS + Android):** один дизайн на обе платформы. Источник правды — `App UI Kit.dc.html` (светлая + тёмная тема), аудит отличий от сайта — `APP_AUDIT.md`, код — `app/` (Bloc/Cubit, go_router, Widgetbook, ARB ru/kk). Любой новый элемент — сначала в App UI Kit и `lib/ui` + Widgetbook. Зона касания ≥ 44. Фото товаров на белой подложке и в тёмной теме. Push спрашиваем после первого заказа; Face ID предлагаем после первого входа; Карта в приложении — flutter_map + тайлы Mapbox (одна реализация для iOS/Android/браузера); ключи через `--dart-define-from-file=env.json`, файл не коммитим.
**Перенос в Flutter:** экраны и компоненты переносятся 1:1 с макетов 390 (порядок блоков, размеры, цвета, тексты), без Material-заменителей (иконки таб-бара, степпер, чекбоксы — геометрией как в макете). Отличия — только системные из `APP_AUDIT.md`. Карта соответствия и статус сверки — `app/docs/PORT_MAP.md`; у каждого виджета в doc-комментарии указан исходный `.dc.html`.
**Push (приложение):** каталог — `app/lib/core/push.dart` и `docs/APP_SPEC.md`; статусы и бонусы вкл. по умолчанию, акции и забытая корзина — opt-in. Согласия на аналитику нет. Юр. документы — пункты «Документы» в Настройках со ссылками-заглушками, тексты напишет бизнес.

**Сторисы и баннер главной:** `MartStories.dc.html` (`mode` desktop/mobile) — ряд прямоугольных миниатюр (88×116 mobile / 104×140 desktop, радиус 18, название белым внизу на затемнении; непросмотренные — розовое кольцо #EE1D74, просмотренные — #E3E2E7, `localStorage 8mart.storiesSeen`). Просмотр: desktop — карточка 400×711 по центру + стрелки, клик по фону закрывает; mobile — на весь экран. Прогресс-полосы, автопереход `STORY_DURATION` (6 с), тап слева/справа — назад/вперёд, удержание — пауза, свайп вниз — закрыть, свайп вбок — соседняя история, ←→ Esc Пробел. CTA: переход (`href`) или копирование кода (`copy`, «Код скопирован»). Данные — `STORIES`, `BANNER` в data.js (мок, в API `GET /stories`, `GET /banners`). Картинки сгенерированы в Magnific без текста, текст — вёрсткой.

**Решения по сайту (Next.js), октябрь 2026:**
- Макет (`site/*.dc.html`) и тексты расходятся — прав макет; расхождение — в `DESIGN_NOTES.md` (корень репозитория), работа не останавливается.
- «В корзину» / «Выбрать размер» в карточке — 36, pill, #F7F7F8, текст #17151A 14/600.
- Фокус MartButton — двойное кольцо `--focus-ring-button` (0 0 0 3px #FFF, 0 0 0 5px #EE1D74); инпуты, чипы и остальное — `--focus-ring`.
- Сайдбар: главная и каталог — 260 (`--desktop-cols`), кабинет — 280 (`--desktop-cols-account`).
- Все тексты интерфейса (ошибки, пустые состояния, тосты, статусы) — в `lib/copy.ts`; придуманные при вёрстке помечены «TODO: согласовать с бизнесом».
- Порог бесплатной доставки 20 000 тг — только в конфиге (`DELIVERY.freeFrom`).
- Бонусы в моке: «Начислено за заказ» = `bonusFor(items заказа)`, баланс — сумма истории.
- Модалка способа получения сама открывается на главной один раз за сессию (sessionStorage) и только если способ не выбран; иначе — по клику в шапке и при попытке добавить товар без способа. Крестик — всегда.
- Полки главной: mobile — 2 карточки, desktop — 4; «Все →» ведёт в каталог («Выгодная полка» — каталог со скидками).

- Модалка способа получения — на весь экран (desktop: карта на всё окно и панель 420 справа; mobile: карта сверху, панель снизу).
- Над пином адрес не пишем — он в поле «Улица, дом» под картой; пока адрес по пину определяется — лоадер в самом пине.
- Подъезд и квартира — только на оформлении (и в адресной книге кабинета), не в выборе способа.
- Поиск адреса — отдельное окно по нажатию на поле: сверху поле, ниже город раскрывающимся списком, затем подсказки только по этому городу; введённый текст в подсказке выделен.
- Самовывоз: список точек — компактные строки, чтобы на экране помещалось больше точек.
- Карта на mobile — одной высоты в доставке и самовывозе. Кнопки «Показать ближайшие» в списке нет.
- Точка самовывоза показывает статус по графику («Открыто до 22:00», «Закроется через 10 мин», «Закрыто до 09:00 завтра»), график — рядом, по времени Казахстана.
- В модалке способа нет подзаголовка «Цены и наличие зависят от филиала». На карте — зум «+ / −» и «Моё местоположение», и на desktop, и на mobile.
