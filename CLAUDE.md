# CLAUDE.md — сайт 8mart

Положите этот файл в корень репозитория сайта. Дизайн-пакет — папка `design_handoff_8mart_site/`.

## Источник правды
1. `DESIGN_RULES.md` — продуктовые правила. Их не переспрашивать и не менять без согласования.
2. `README.md`, `COMPONENTS.md`, `tokens.css` (эта папка) — размеры, цвета, состояния.
3. `site/*.dc.html` — визуальный референс (запуск: `cd site && npx serve .`). Если что-то не описано в текстах — смотреть в HTML и брать точные значения из inline-стилей.

## Правила
- Верстать 1:1 с артбордами 1440 / 390. Никаких «похожих» значений: цвета, радиусы и высоты берутся только из `tokens.css`. Высоты контролов — 36 / 40 / 44 / 56 (textarea 84).
- Шрифт — только Onest из `fonts/` (перенести в `public/fonts`). Google Fonts в проде не подключать.
- Повторяющийся (≥3 раз) или имеющий состояния элемент — отдельный компонент. Новый элемент сначала добавить в витрину `/kit`.
- Одно значение — одно место: пороги, тарифы, тексты ошибок и блокировок CTA лежат в одном модуле конфигурации, а не в двух экранах.
- Иконки закрытия и стрелки — SVG/CSS, не символы шрифта.
- Деньги — только через `money()`: `4 090 тг.`.
- Данные — через `lib/api.ts`. Мок держать в той же форме, что и API-контракт в README.
- Секреты (Mapbox, DaData) — в `.env.local`, не в репозитории. DaData вызывать только с сервера (route handler `/api/geo/*`).
- Доступность: зона касания ≥ 44, кастомный focus-ring, Esc закрывает модалки, sheet и сторис.
- Маленькая правка — меняй только её.
- Любое новое правило, которое объяснил пользователь, — дописывать в `DESIGN_RULES.md`.
