# AGENTS.md — для ИИ-агента, который подключает бэкенд к сайту 8mart

Фронт готов и согласован с владельцем продукта. Твоя задача — соединить его с бэкендом, **не меняя экраны и поведение**.

## Прочитай сначала

1. [BACKEND_HANDOFF.md](BACKEND_HANDOFF.md) — все эндпоинты, формы ответов, временные адаптеры, localStorage, оплата, открытые вопросы.
2. `lib/types.ts` — формы данных. Это контракт.
3. `lib/api.ts` + `lib/http.ts` — единственная точка доступа к данным и переключатель мок / API.
4. `design_handoff_8mart_site/DESIGN_RULES.md` — продуктовые правила (отправления, доставка, вход, оплата).

## Граница

- **Экраны и компоненты не делают `fetch`.** Все данные — через функции `lib/api.ts`. Нужен новый запрос — новая функция в `lib/api.ts` с JSDoc `/** METHOD /path */` и моком.
- **Сигнатуры функций `lib/api.ts` и типы `lib/types.ts` не менять** без согласования. Ответ бэкенда другой формы — переводить внутри «настоящей» ветки `endpoint(...)`, а не в экранах.
- **Мок не удалять**, пока эндпоинт не заработал на проде: он нужен для разработки без бэкенда и для тестов.
- **Вёрстку, тексты (`lib/copy.ts`), тарифы и пороги (`lib/config.ts`) не трогать.** Если значение должно прийти с сервера, сначала спроси.
- `lib/domain/*` — предварительный расчёт на фронте (итоги, отправления, слоты). Источник правды — бэкенд; формулы должны совпадать (см. тесты `lib/domain/*.test.ts`).

## Как подключить эндпоинт

1. Найди функцию в `lib/api.ts`. Она уже имеет вид `endpoint('имя', () => apiFetch('/путь', …), () => мок)`.
2. Сверь путь, метод, query и тело с бэкендом. Если что-то отличается — поправь «настоящую» ветку.
3. В `.env.local`: `NEXT_PUBLIC_API_URL=<адрес>`. Ещё не готовые эндпоинты держи на моке: `NEXT_PUBLIC_API_MOCK=getOrders,getBonus`.
4. Когда весь блок работает через API, удали связанные `TEMP-ADAPTER` (`grep -rn TEMP-ADAPTER app lib scripts`) и обнови таблицу статусов в `BACKEND_HANDOFF.md`.

Вход: после `authVerify` экран кладёт `accessToken` в `lib/store/auth.ts`. `apiFetch` подставляет его в `Authorization: Bearer` (провайдер регистрируется в `components/site/SiteOverlays.tsx`). Refresh — httpOnly cookie бэкенда (`credentials: 'include'`). Обновление токена по 401 пока не сделано — добавь в `apiFetch`, когда будет `POST /auth/refresh`.

Ошибки: бросай `ApiError(status, message)`. Экраны различают 404 (не найдено), 409 (корзина изменилась / заказ уже в доставке), 400 на `authVerify` и `verifyPhone` (неверный код). Остальное показывается как сбой.

## Проверка

```bash
npm run typecheck && npm test && npm run build
```

Все три должны проходить. Тест переключателя — `lib/http.test.ts`. Пройди руками: главная → каталог → товар → корзина → способ получения (доставка и самовывоз) → оформление → заказ → кабинет, на 1440 и 390 px.

## Нельзя

- Коммитить ключи (`.env.local` в `.gitignore`). DaData и секретные ключи — только на сервере.
- Менять `DESIGN_RULES.md` без согласования с владельцем.
- Ставить новые зависимости без причины. Для запросов хватает `apiFetch`.
